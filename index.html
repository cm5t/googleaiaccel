02 · Data and targets

What one training example contains

The code converts each annotated cell into several learning targets. This gives the small model more useful signals than a single “cell / not cell” label.

Input and annotations

A 512 × 512 RGB patch is paired with CSV rows that contain pixel coordinates.

  • Centroid X/Y: the labelled centre of each cell.
  • Max/min caliper: used to estimate a radius as 0.5 × √(max × min), under the current assumption that calipers are full axis lengths.
  • Approximate mask: a filled disk around each centre, clipped to the image boundary.

Training-only variety and background balance

Augmentation is applied only to training crops: flips and right-angle rotations change orientation, while modest brightness, contrast, saturation and channel-gain changes vary appearance. A scale change is sampled occasionally between 0.90× and 1.10×, and the cell centres, radii and targets are transformed with the pixels. Each fold retains every positive crop and samples at most half as many empty crops as positive crops. Validation remains unaugmented and keeps all its patches.

Why predict several targets?

The centre map answers “where is a cell?”, foreground answers “which nearby pixels belong to cell-shaped regions?”, offsets correct the coarse two-pixel output grid, and radius supplies a size estimate. The density map is a separate auxiliary count signal: every point’s Gaussian is normalized to one unit, so nearby kernels can overlap without changing the total target count. The detector still creates individual instances from centre peaks; the density map does not add a second set of detections.

i
Annotation assumption: the CSV provides centre coordinates and caliper measurements, not traced outlines. The current radius formula assumes both calipers are full axis lengths, then halves the geometric mean. Generated circular masks are therefore pseudo-labels for training and mask metrics, not verified cell boundaries. Border clipping keeps a cell target usable when its estimated circle extends beyond the image.

04 · The network

CentroidLite predicts six maps at once

The compact network trades a large object-detection stack for a small set of dense maps. Its smaller architecture aims to reduce compute; actual speed still depends on hardware, data loading and cell density.

Small output map: a 512-pixel patch becomes 256 × 256. The parallel dilation-1/2/4 branches mix local nuclear texture and wider tissue context. Learned offsets recover sub-grid centre precision, and the initial density bias is chosen to avoid an almost-closed softplus gradient.
The training objective
L total = L centre + L foreground + 2L offset + L radius + 0.08L density + 0.10L log-count

Centre uses focal-style supervision and mines difficult negatives. Foreground combines weighted binary cross-entropy with Dice loss. Density uses pixelwise Smooth L1 against normalized point kernels; log-count compares the sum of predicted density with the exact labelled cell count. The density map also supplies a modest candidate-score agreement cue. Loss scales depend on the architecture and reduction rules, so raw total loss should not be compared directly with unrelated models.

↻
Recoverable training: the loop writes progress checkpoints during an epoch, including model and optimizer state, batch order and the next sample position. If a batch exceeds MPS memory, the code can halve the batch size and retry from saved progress.

What gets logged and saved?

The run prints a progress bar and a persistent summary every 100 batches with recent loss components, throughput and time spent waiting for data. A resumable state is refreshed every ten completed batches, including model, optimizer, scheduler, scaler, fixed epoch order and next sample offset. A separate model-weight file is saved after each completed epoch. If MPS memory runs out, the loop can lower batch size and retry from the last saved position; an interrupted accelerator operation is not guaranteed to be recoverable.

Why macOS starts with zero data workers

The notebook uses zero DataLoader workers by default on macOS because spawned Jupyter workers previously failed to import the dataset class and could increase memory pressure. The separate cell_dataset_workers.py makes dataset definitions importable if workers are deliberately enabled. More workers are not automatically faster on a memory-limited Mac; compare batches per second and data-wait time on the actual machine.

Why group by image instead of randomly splitting patches?

Nearby patches from the same slide can look very similar because they share stain, scanner, tissue and preparation characteristics. If patches from one image appeared in both training and validation, validation could reward recognition of slide-specific patterns. Holding out the whole image asks the harder and more useful question: can the model work on a different image group?

What goes into the training and validation side?

Each training fold keeps every cell-containing patch and adds a reproducible sample of empty patches: up to 0.50 empty patch per positive patch. This gives the detector examples of annotated background without letting a very large number of empty crops dominate each epoch. Validation uses the complete held-out patch set, including empty patches. Where edge-anchored crops overlap, ownership-core bounds assign each labelled centre to one validation crop so it is not counted twice.

Does each fold contain exactly one-third of the images?

Not necessarily. The splitter assigns whole image groups and balances patch and annotated-cell totals; it cannot split an image. A very large or cell-dense image can make exact fractions impossible. The setup prints each fold’s groups, patches and annotated-cell totals for inspection.

What does the epoch cap mean?

Stage 1 allows up to 10 epochs in each of 3 folds (up to 30 CV fold-epochs), plus a final all-data refit capped at 10 epochs. The final refit uses the median selected best epoch from the three folds. Early stopping or a lower median can reduce the total; the 40-epoch figure is a ceiling, not a promise.

How does a fold choose its checkpoint?

The primary fold metrics use a pre-set 0.10 score cutoff; threshold-calibrated metrics are reported separately. Predicted centres are matched one-to-one to labels within 12 pixels. The matcher searches for the largest valid match set, so an early nearest-pair choice cannot unnecessarily block another possible match in a crowded area. Checkpoint selection combines fixed-cutoff F1 (45%), the weaker of precision/recall (25%), and normalized count skill (30%). The scheduler watches fixed-cutoff F1. From epoch 3, later weights are averaged (SWA); the averaged model is used only when its declared validation selection score improves.

What is the difference between cross-validation and the final refit?

The three fold runs estimate how the model behaves on held-out image groups and select the median best epoch. The final refit starts a fresh model and trains on all eligible training patches for that many epochs, capped at 10. It has no held-out group of its own, so cross-validation—not the final fit—is the generalization estimate.

How are Stage 1 and Stage 2 evaluated across folds?

Stage 1 scores held-out patches using centre matching. Stage 2 loads the corresponding fold’s best checkpoint and evaluates complete held-out images with overlapping tiles and de-duplication. This lets the code measure seam errors and whole-image counts without using that fold’s held-out labels to update model weights.

Why can validation take time?

Every fold validates its held-out patches at each epoch. Detection validation sweeps several score thresholds. At the end of a fold, Dice, AJI and PQ require instance-mask comparisons on its best checkpoint, which is a separate and more expensive pass.

How to read a fold result responsibly

A fold line is a small report card for one held-out set. Read the detection measures together and compare the same metrics across all three folds.

  • Training loss falls, validation F1 rises: encouraging, provided the other folds show a similar pattern.
  • Loss falls but validation F1 stalls or falls: the model is fitting the training examples without improving held-out detections; more epochs alone may not help.
  • Low precision or positive count bias: there are likely too many predicted centres. Raise confidence threshold only if validation shows that precision improves without unacceptable recall loss.
  • Low recall or negative count bias: cells may be missed. A lower cutoff may recover detections but can also admit false positives.
  • One fold is much worse than the others: inspect its held-out images for staining, scanning, tissue density or annotation differences before changing the network.
  • Any NaN loss: treat it as a numerical warning. Validation can still produce finite scores from the saved weights, but the affected epoch’s reported mean loss is not trustworthy and the batch that first became non-finite should be investigated.

07 · Whole-slide use

Stage 2 tiles, overlaps and stitches

Stage 2 is an inference and assembly procedure around the same trained model. It handles cells near crop boundaries and merges repeated views.

A

Overlap tiles

512-pixel crops use a nominal 384-pixel maximum step, giving at least 25% overlap. Starts are spread evenly and the last crop is anchored to the far image edge.

B

Shift to slide space

Each crop's centre, box and mask coordinates are shifted by its slide origin.

C

Fuse repeat views

Only candidates from different tiles can merge. Radius-aware centre distance plus mask IoU or containment must support a duplicate; same-tile neighbours stay distinct.

D

Write outputs

Optional global label map, detection CSV, JSON metadata and coloured overlay.

Why overlap matters

A cell cut by an internal crop edge may look incomplete. Another tile can show it with more context. The code scores each view using detector confidence and distance from an internal cut, scaled by the estimated cell radius; a small nucleus does not need the same margin as a large one. Real outer slide borders are not treated as artificial crop seams. Repeated centres, boxes, radii and scores are combined with quality-and-confidence weights, while the strongest view supplies the instance mask.

How it avoids unsafe merging

The stitcher compares packed instance masks in slide coordinates. Close candidates need sufficient overlap or containment; candidates beyond the standard centre-distance range need stronger mask agreement. A cluster may contain at most one candidate from any one tile, which prevents a third partial view from joining two neighbouring cells that were visible together in the same tile. These are explicit duplicate rules, not a guarantee that every merge is correct.

How the code checks stitching

Each fold’s held-out source images are processed at a fixed 0.10 detection cutoff using that fold’s best Stage 1 checkpoint. Stage 2 reports full-image precision, recall, F1, count MAE and exact-count accuracy, then separately reports a 32-pixel seam band, the full overlap region, and tile interiors. It also reports the fraction of final detections supported by multiple tile views and the mean contributing views. A held-out example can be exported as an instance-label map, per-cell CSV, JSON metadata and coloured overlay.

↗
Read seam results as a diagnostic: similar seam and interior F1 suggests that crop boundaries are not the only source of error. Lower seam scores point toward truncation or duplicate handling. Higher seam scores do not prove the stitcher is better; compare the same held-out images, threshold and fold assignments.

The model reports positive-class precision/recall/F1, specificity, balanced accuracy, PR-AUC and per-case summaries. Class weighting and case weighting are computed from each training fold only.

The proposed research workflow begins with an interpretable DAB optical-density baseline inside the annotated nucleus, supported by hematoxylin and local context. Then compare RGB and RGB+H/DAB crop CNNs on identical case folds. Evaluate probability calibration and class-specific precision/recall as well as PR-AUC; a high overall accuracy can hide a missed minority class. The current executable path is the crop CNN, not the DAB baseline.

10 · Read this carefully

What this model does not prove

Research prototype, not a clinical tool.

The masks are approximate circles derived from centroid and caliper labels; they are not manually traced cell boundaries. Training retains every cell-containing patch and samples empty patches at 0.50 per positive patch; validation keeps the full held-out patch set, including empty patches. The threshold sweep and all reported metrics still need to be checked on held-out data. Dice, AJI and PQ are measured against caliper-derived circular pseudo-masks, not manually traced boundaries. This guide uses invented examples only; it does not load confidential images, CSVs, model weights or checkpoints and does not promise a target score.

Project 2: Detailed Speaker Notes and Model Improvement Record

These notes explain the current Project 2 cell model in presenter-friendly language. They follow the pipeline from the annotated images to training, validation, and stitched whole-image predictions. They also record the current notebook settings and the substantive code changes made to address the failure patterns seen in the supplied logs. This document describes the implementation in Project 2 Stage 1 and 2 Complete.ipynb and cell_dataset_workers.py; it does not claim that any change has improved scores until a fresh, comparable validation run confirms it.

1. Opening: what problem are we solving?

Speaker notes

“Project 2 asks us to find individual cells or nuclei in high-resolution DLBCL tissue images, outline them, and count them. The input is a stained tissue image plus a table of annotated cell-centre coordinates and measurements. The output should be a set of individual detections, each with a centre, a mask or outline, a bounding box, and a count.

“The images are much larger than a normal neural-network input, so we process them as smaller image tiles. This creates two linked tasks. Stage 1 learns to recognize cells inside a tile. Stage 2 runs that same learned model across overlapping tiles and combines the results back into one whole-image result.”

“The current default is a compact centre, foreground, and density model called CentroidLiteNet. The notebook now has two runnable code cells: shared setup, then a combined Stage 1–3 pipeline. The second cell runs Stage 1 training and tile checks, continues to Stage 2 overlapping-tile inference, then reaches the optional Stage 3 classifier section. Stage 3 design notes are kept as comments in that same cell. The same Stage 1 network is used for Stage 2; Stage 3 is a distinct classifier that runs on detected cell crops, with classifier training disabled by default.”

2. What the labels do and do not tell the model

Speaker notes

“The available labels tell us where a cell centre is. They do not provide a manually traced outline for every cell. The code estimates a radius from the recorded maximum and minimum caliper measurements, then creates a circular training mask around the centre. It assumes the calipers are full axis lengths, so it uses half of their geometric mean as the radius. A fallback radius is used when the measurements are missing or invalid, and the result is clipped to a configured minimum and maximum.”

“The brief’s ‘different colour map’ figure is a visualization of the pathologist’s centroid annotations: it shows marked centre points and an overlay on the source image. It does not prescribe recolouring the image to find cells. The model already uses those centres to build a centre heatmap target. A separate stain-separation experiment is still reasonable, but it is an additional preprocessing experiment, not what that figure itself describes.”

“This lets us train and score a mask-producing model even though traced contours are unavailable. It also sets a limit on what the mask scores mean: Dice, AJI, and PQ are measured against caliper-derived circular pseudo-masks. They are useful for checking whether the model reproduces its constructed targets. They do not prove that the predicted boundary matches the true biological boundary. A manually traced subset would be needed to make that claim.”

“All annotated objects currently use one foreground class, called cell. The code does not train a BCL6-positive versus BCL6-negative classifier. That is a later classification task, after cell finding and counting are reliable.”

3. Preparing tiles and retaining border cells

Speaker notes

“A tile is a square crop, currently 512 by 512 pixels. The code reads each image’s dimensions and the matching annotation table, then assigns each cell centre to every crop that contains it for training. The crop coordinates are retained so a predicted local point can later be converted back into the original image coordinates.”

“The old grid placed most crops one patch-width apart and then shifted the final crop to the far edge. In some image sizes, that made the last two training crops overlap almost completely. The updated grid uses the same number of crops but spreads the necessary overlap more evenly. For example, a 1600-pixel axis with 512-pixel crops now starts at approximately 0, 363, 725, and 1088 pixels. This avoids giving the far edge a disproportionate number of nearly repeated examples.”

“When a crop extends beyond a small image edge, PIL would normally fill the missing area with black. Black padding is unlike the surrounding tissue and can teach the network an artificial edge cue. The worker module now extends the last real row and column into the padded area. The valid image width and height are still tracked, so padding is excluded from evaluation and output masks.”

“For validation, neighbouring crop regions overlap. The code splits that overlap into ownership regions. A reference cell and a prediction are counted in one owner region only. This avoids counting the same cell twice just because it appears in two crops. For training, the image remains available in overlapping crops to provide varied context.”

“The setup indexes image dimensions, annotation coordinates, crop starts, and ownership bounds once, then reuses that metadata for the training and validation views. The fold splitter is implemented locally rather than importing scikit-learn, avoiding a slow or interrupted dependency import during notebook startup. It keeps each source-image group intact and greedily balances both patch volume and annotated-cell counts. It is not a patient-level split unless the group key is changed to a patient or case identifier.”

4. Augmentation and empty-background examples

Speaker notes

“Training augmentation makes plausible variations of the same labeled crop. The code flips and rotates the image and transforms the cell coordinates along with it. For the centroid model, it also applies a mild, occasional isotropic zoom between 0.90× and 1.10×; it resizes the crop, shifts the centre coordinates, and scales the caliper radii together. A zoom-in is skipped if it would crop any labelled centre, avoiding false targets at the crop edge. This exposes the model to modest cell-size variation. It also makes brightness, contrast, saturation, and channel-gain changes. Validation uses unaugmented images so it measures the model on the original inputs.”

“One important precision issue was that training excluded every tile with no annotated cells. Validation still contained those empty tiles. That meant the model was asked to avoid false positives in backgrounds it had never seen as a training example. The current experiment keeps every cell-containing crop and samples empty crops at 50% of the positive-crop count. This is a measured increase from 35%, intended to reduce background false positives and over-counting. It adds roughly 11% more training tiles than the previous 35% setting, and can hurt recall if the supposedly empty crops contain unlabelled cells.”

“The worker code now augments sampled empty crops too. They remain empty after flips and rotations, so they teach the model what background can look like under the same image transformations as positive examples.”

“The centre loss also mines more difficult background locations within each patch: the negative-to-positive mining ratio has increased from 64 to 96, with the existing per-patch cap of 2,048 mined locations. The positive-centre emphasis remains at 1.5. This aims to teach a sharper boundary between true centres and stain texture while retaining a strong signal for annotated cells. Both changes target false positives; they may reduce recall if labels omit real cells, so the next run must compare precision and recall together.”

“The scale jitter is not applied to validation, and it is not meant to simulate severe zoom changes. It is a controlled geometric augmentation: image pixels, centre coordinates, and estimated radii are transformed together so target geometry stays aligned.”

“The current Stage 1 objective removes the approximate centre-heatmap-mass consistency shortcut. It adds a spatial density target: every annotated centre contributes a Gaussian whose values are normalized to sum to one, so the total target-map mass equals the exact number of annotated cells, even when nearby Gaussians overlap. A pixelwise density loss teaches where the cell mass belongs, and a log-count loss supervises the sum. This density head is an auxiliary task; the centre detector still proposes individual cells.”

5. The network: how it produces a cell prediction

Speaker notes

“The model first reduces the input from 512 by 512 to 256 by 256 using average pooling. It then extracts image features with a small convolutional stem and residual depthwise-separable blocks. A depthwise convolution looks at nearby pixels independently per feature channel; a pointwise convolution mixes information across channels. This is a lighter operation than a full convolution over every input and output channel.”

“The blocks also include a small channel gate. It summarizes the feature map and learns which channels deserve more emphasis for the current image. The model is intentionally compact because training runs locally on Apple MPS and memory and runtime have been recurring constraints.”

“The current Stage 1 recipe uses parallel depthwise branches at dilation one, two, and four. One branch emphasizes local nuclear texture; the wider branches include neighbouring tissue and nearby nuclei. A gated residual fusion combines those views back into the same compact 24-channel feature map, followed by a local refinement block. The parallel branches give each location local and wider context at once, while keeping the detector output stride unchanged.”

“The spatial head now produces six maps: centre confidence, foreground confidence, horizontal centre offset, vertical centre offset, normalized radius, and a nonnegative density map. There is no separate globally pooled scalar-count head. Instead, each annotated centre contributes one unit of target density, and summing the predicted map estimates the number of cells in the tile. The initial density bias was raised from an almost-zero value because softplus has a very small gradient far below zero; the new initialization gives the map a plausible starting scale and a more useful learning signal. Validation reports the density map’s tile-count MAE and signed bias alongside the detector’s image-level count metrics.”

“At inference, the decoder first finds local peaks in the centre map. It blends 30% foreground support and a modest 15% relative density support into each candidate’s score; the centre head remains the main source of candidate locations. A four-pixel minimum-distance suppression removes nearly coincident duplicate peaks, and each surviving peak is refined with the offset map. The density head does not create a second proposal list, which avoids an independent set of duplicate detections. These score blends can change precision and recall without changing the learned weights, so they must be judged on the held-out folds.”

“RGB is still the default input. There is now an optional rgb_hdab ablation that keeps the original RGB channels and adds two approximate optical-density channels: hematoxylin and DAB. Hematoxylin tends to reveal nuclei; DAB carries the BCL6 immunostain signal. The same conversion is applied to training, Stage 1 full-image inference, and Stage 2 tile inference. The channel planes can be previewed before switching modes.”

“The H/DAB vectors are generic starting values. Stain concentrations and scanning can vary by laboratory, so a deconvolution can be inaccurate if those vectors do not fit these slides. Keep RGB as the baseline, inspect the H/DAB preview, then compare the two modes using the same folds and settings. The H/DAB mode changes the model’s first convolution and requires a fresh training run.”

“The default compact model starts from random weights. The optional Mask R-CNN reference can use a pretrained ResNet backbone, but it is slower and depends on torchvision startup and compatible weights. The current changes do not add a pretrained model; they improve the compact network’s context and supervision while preserving its lighter runtime profile.”

6. How training targets are built

Speaker notes

“Each annotated centre becomes a small Gaussian-shaped peak on the centre heatmap. The peak gives the network a smooth target around the centre instead of a single isolated pixel. At the exact peak location, the offset targets record the fractional position between the cell centre and the nearest output-grid point. The radius target records the caliper-derived radius on a normalized zero-to-one scale.”

“The foreground target is a low-resolution union of the circular pseudo-masks. It says which pixels belong to any cell-like region. The regression mask marks the grid locations where an offset and radius target exist. Those size and position losses are calculated at annotated centres rather than at every background pixel.”

“Several nearby cells can have overlapping foreground regions. The instance decoder uses the predicted centres as seeds and assigns foreground pixels to the nearest seed when they fall inside that seed’s predicted radius. That turns one shared foreground map into separate instance masks.”

Point-density design note

Speaker notes

“The new density map is a point-supervision idea: each labelled centre contributes a normalized spatial kernel, and the total map mass equals the number of points. That gives a local count target and an integrated count target at once. The implementation remains a compact convolutional centre detector; it is not P2PNet and does not use P2PNet’s Hungarian point-proposal matching. P2PNet is relevant as evidence that point-based detection/localization can avoid full pixel masks for dense-object counting (ICCV 2021 paper); CellRegNet is a cell-imaging example of point annotations supporting density regression (paper). The validation density tile MAE/bias tells us whether this extra head learned useful count information; only the centre detections determine the final cell list and count.”

7. What the loss means

Speaker notes

“The training loss is a weighted sum of several jobs. The centre heatmap loss is focal-style: it emphasizes missed centres and the hardest false-positive locations, while easy background pixels contribute little. Hard-negative mining selects a limited set of challenging background positions so the network does not spend most of its work on obvious empty pixels.”

“The foreground loss combines weighted binary cross-entropy with Dice loss. Binary cross-entropy gives a pixel-level learning signal. Dice helps with the imbalance between a small cell foreground and a large background. In the current configuration, Dice supplies most of the foreground-loss share.”

“The offset loss teaches the model to refine centre locations. The radius loss teaches the approximate cell size. The new density-map loss compares a spatial count map with the normalized point targets, while the log-count loss compares the total predicted density with the exact number of labelled centres in the tile. The density head also provides a small agreement cue when ranking centre proposals. Each term measures a different behavior, so the total loss is not directly comparable to the total loss from a different architecture or a different loss formula.”

“A total loss around four does not, by itself, prove the model is bad. A different model can report a loss below two because its terms, reduction rules, scales, and target definitions differ. For this task, held-out precision, recall, F1, count error, and appropriately interpreted mask metrics are more useful than comparing raw loss numbers across unrelated code.”

8. The training loop and saved progress

Speaker notes

“At the start of each batch, the loader supplies images and their target maps. The model predicts its six spatial output maps, the loss function calculates all terms, gradients are computed, and AdamW updates the model. Gradient clipping limits a single batch from making an excessively large update.”

“Training logs report the current loss, a smoothed loss, speed, throughput, data-wait percentage, and the recent average of each loss component. These are diagnostic signals. A lower batch loss means the training targets are being fit more closely; it does not establish generalization to held-out slides.”

“The code saves a resumable checkpoint periodically and an epoch model file after each completed epoch. It preserves the model, optimizer, scheduler, scaler, batch order, and progress position, so an interruption can continue from a known batch. The updated loop checks the loss before backpropagation and checks the gradient norm before the optimizer step. If either becomes non-finite, it stops before saving contaminated weights and reports the image names and loss components. This is aimed at diagnosing the NaN run seen in the supplied logs.”

“The resume file is refreshed every ten completed batches. A separate epoch-weight file is saved when each epoch finishes, so a completed epoch remains available even if a later epoch is interrupted. Resume compatibility checks include the fold split and training recipe; incompatible resume state is archived instead of being applied to a different set of tiles. On an MPS out-of-memory error, the resumable loop can lower the batch size and retry from the latest saved batch state. This is a recovery path, not a guarantee that every interrupted accelerator operation can be recovered.”

“To make a slow start visible, the loop says when it is waiting for its first batch and reports when that batch arrives. It then prints a persistent batch summary every 100 batches, including recent loss components, throughput, and data-wait time. On macOS the default worker count is zero because spawned notebook workers previously caused import and memory failures. The separate worker module makes the dataset and collator pickleable if workers are deliberately enabled on a suitable setup; more workers are not automatically faster on a memory-limited Mac.”

“From epoch three onward, the code maintains a simple equal-weight average of later model parameters (SWA) and validates that averaged state. This can smooth noisy parameter updates, but it is only retained when the declared validation selection score improves. The checkpoint stores the model state and validation history needed to continue or audit the run.”

9. Validation: how the scores are calculated

Speaker notes

“Validation switches the model to evaluation mode and disables gradient tracking. It predicts each validation crop, keeps only predictions in the crop’s ownership region and real image area, then matches predicted centres to annotated centres within a 12-pixel distance.”

“The previous matcher greedily accepted the closest pair first. In a crowded example, that first choice can block a second valid match even when another one-to-one assignment could match both cells. The updated matcher uses augmenting paths on the sparse graph of allowed prediction-to-label pairs. It finds the largest possible one-to-one match set within the distance limit. This corrects the metric calculation; it does not change the model’s predictions.”

“Precision is the fraction of predicted cells that match a reference centre. Low precision usually means too many false positives. Recall is the fraction of reference cells found. Low recall usually means cells are missed. F1 is the harmonic mean of precision and recall, so it penalizes a system that is strong on only one of the two.”

“Count MAE is the mean absolute difference between predicted and reference counts across validation images. Count bias is signed: positive means overcounting on average; negative means undercounting. Exact-count accuracy is strict: an image counts as correct only if its predicted total equals the reference total exactly.”

“The code scans a wider confidence range, from 0.01 through 0.90. For each candidate cutoff, a count-aware score combines F1 (45%), the weaker of precision and recall (25%), and count skill (30%). Count skill is 1 / (1 + relative count MAE / 100), so it is on a 0-to-1 scale and penalizes large image-count errors. The fixed, pre-set cutoff of 0.10 remains separately reported for fair comparisons. Since threshold selection uses validation labels, treat the calibrated cutoff as a deployment candidate and confirm it on separate cases before making a final performance claim.”

“The best Stage 1 checkpoint is also selected with this stated fixed-cutoff composite. The scheduler still follows fixed-cutoff F1, so the checkpoint-ranking rule and learning-rate rule are intentionally visible as separate choices. The summary reports fixed-cutoff results as the primary CV values and calibrated-threshold results as a diagnostic. This makes it harder for each fold’s tuned threshold to inflate the main cross-validation comparison.”

10. What Dice, AJI, and PQ tell us

Speaker notes

“Dice checks foreground pixel overlap. It answers whether predicted cell pixels and reference cell pixels cover similar areas. In this notebook it is computed on the union of the instance masks, so it is a foreground-overlap score.”

“AJI, the Aggregated Jaccard Index, is more instance-aware. It tries to match predicted objects to reference objects and combines their intersection and union. Unmatched objects add area to the denominator, so missed and extra objects hurt the score.”

“PQ, Panoptic Quality, combines recognition and segmentation quality. A predicted object has to match an individual reference object with sufficiently strong overlap to count as a true positive; then the matched IoUs are averaged while false and missed objects are penalized.”

“These numbers can remain low when centres are missed, when extra predictions are present, or when predicted radii differ from the constructed pseudo-mask radii. In this project they are calculated against circles built from centre and caliper data, not traced cell boundaries. We should label them ‘pseudo-mask Dice/AJI/PQ’ and state this limitation every time we present them.”

“To keep routine validation faster, the current run does not recompute these mask metrics at every epoch. It refreshes Dice, AJI, and PQ on the selected best checkpoint for each fold. That is why an epoch line can say ‘mask metrics at best epoch’ while the other detection and count statistics update each epoch.”

11. Why there are three folds and ten epochs

Speaker notes

“Three-fold cross-validation divides the source image groups into three parts. For each run, roughly two parts train the model and the remaining part validates it. The held-out part rotates, so each image group is used for validation once. Compared with five folds, each validation split is larger and each fold has less training data. Three folds reduce the number of separate fits, but the estimate can vary more with which images land together.”

“The split is by image stem, so tiles from one source image stay in the same fold. This prevents nearly identical crops from one slide appearing in both training and validation. If several source images belong to the same patient, the grouping should be upgraded to patient ID; otherwise related slides could leak across folds.”

“Three folds are not three models that get averaged together for the final prediction. They are three evaluation runs. After cross-validation, the notebook trains one final model on all eligible training groups, using the median best epoch from the folds, capped at ten epochs. Stage 2 inference then uses that single final model.”

“The current cap is ten epochs per fold, followed by a final refit of up to ten epochs. Each fold begins with fresh weights. Early stopping patience is also ten, so it will not normally stop before the ten-epoch cap due to a short plateau. Fold-to-fold variation is important evidence: a model that looks good on one fold but poor on another is not stable yet. Cell 2 prints a run fingerprint with recipe ID, fold count, epoch cap, density blend, and checkpoint folder so logs can be matched to the code that produced them.”

“The requested maximum is ten epochs in each of three folds, or up to 30 CV fold-epochs, followed by a separate final refit capped at ten epochs. The configured total budget is therefore up to 40 training epochs, although early stopping or a lower median best epoch can reduce the actual amount. Ten is a cap, not a promise that every fold will need all ten.”

“The current splitter greedily balances patch volume and annotated-cell counts while grouping by image filename stem. Stage 2 uses these same shared fold assignments for its held-out full-image checks, although its stitching model and algorithm are unchanged. If several source images belong to one patient, use patient/case ID as the group key before claiming patient-level generalization. Fold count alone cannot prevent leakage if the grouping unit is too small.”

12. Stage 2: rebuilding the full-image result

Speaker notes

“For a large image, Stage 2 lays evenly spaced, edge-anchored tiles across the image. The configured stride is the maximum tile-to-tile gap, so the overlap is at least the nominal 25 percent and any extra overlap is spread evenly. For a 1600-pixel axis with 512-pixel tiles, the starts are 0, 363, 725, and 1088 pixels. It runs the same Stage 1 model on each tile, adds the tile origin to each predicted centre, box, and mask position, and brings all candidates into the original image coordinate system.”

“The previous duplicate rule removed any pair from different tiles whose centres were within 12 pixels. In dense tissue, two real neighbouring nuclei can be that close. The updated rule still uses proximity to find possible duplicates, but it also requires strong agreement between the two masks: sufficient mask IoU or one mask being mostly contained in the other. This better distinguishes two separate nearby cells from two tile views of one cell.”

“A duplicate is only considered when mask overlap or containment supports the match; farther centre pairs need stronger mask agreement. The cluster can contain at most one prediction from any one tile, which protects two close cells seen together in a tile from being collapsed through a chain of matches. The system then fuses the repeated centres, boxes, radii, and confidence with weights based on detection confidence and view quality, while retaining the best-supported single mask as the instance shape. This uses the consistency across overlapping views instead of discarding all but one centre estimate. Remaining mask pixels are written to a disk-backed label map so a whole-slide output does not require multiple huge arrays in memory.”

“The output can include a global instance-label image, a metadata JSON file, a per-cell CSV with centres, boxes, scores and instance IDs, and a visualization overlay. Stage 2 is evaluated separately on held-out full images, including seam and interior precision, recall, and F1. A good tile-level score alone does not show that stitching works.”

“The Stage 2 report keeps narrow edge-band and wider overlap-region scores. The overlap region includes every point covered by multiple tiles, so it can expose duplicate-view errors away from the exact seam. Candidate view quality is based on distance from an internal crop cut relative to the estimated cell radius; the real outer slide border is not penalized as if it were an internal seam. Each fold also reports the share of detections supported by more than one tile and the average number of tile views per detection. These diagnostics show when consensus fusion is actually being used. They do not establish a score improvement until the new algorithm is compared on the same held-out full images.”

“Stage 2 processes several tiles in one inference batch when the device permits, and prints tile-batch progress. Each candidate mask is stored in a compact packed representation while duplicates are compared. When outputs are requested, the instance-label image and ownership-score canvas are disk-backed arrays; detections also produce a metadata JSON, a per-cell CSV with the number of contributing views, and a rendered overlay. The label map assigns overlapping pixels to the representative mask with the stronger tile-view quality score. The output folder and metrics filename use a new v3 run ID, so results from the earlier stitcher remain separate.”

16. Further improvements that need a data-informed follow-up

These are the next high-value experiments after the changed notebook has been run. They are deliberately separated from the implemented fixes because their benefit depends on the actual slide distribution and label meaning.

  1. Create a small manually traced validation set. Trace representative nuclei, including touching, faint, large, small, and border cases. Keep it separate from training. This is the step that makes Dice, AJI, and PQ meaningful as true contour scores. The current caliper circles can remain weak training labels, but they should not be the only evidence of segmentation quality.
  2. Split by patient or case. The current group key is the image filename stem. If one patient contributes several images, use the patient/case ID as the group so related slides cannot appear in both train and validation folds.
  3. Benchmark a domain-relevant pretrained segmenter. HoVer-Net or HoLy-Net is a stronger architecture reference for touching nuclei than the compact centre-plus-radius decoder. Compare the same image groups, centre-match rule, fixed cutoff, and manually traced masks. Published scores from another stain or institution are reference points, not expected scores for this BCL6 task.
  4. Tune the operating cutoff on separate calibration data. The calibrated score in a fold is selected from that fold’s validation examples. The fixed-cutoff line helps expose this. For a more independent deployment estimate, reserve calibration groups inside the training side or use a nested validation design, then evaluate the chosen cutoff on untouched outer groups.
  5. Review false positives and false negatives by type. After a run, inspect only a small, authorized set of overlays and make a short error table: stain texture, debris, overlapping nuclei, weak/fragmented nuclei, crop seams, and label-coordinate mismatch. Use this to choose hard-negative sampling and augmentation changes instead of increasing every loss weight at once.
  6. Ablate centre peak suppression. The decoder now has a conservative four-pixel minimum distance to remove almost-coincident peaks. Compare it with suppression disabled and a six-pixel setting on identical held-out folds. Keep a setting only if the reduction in false positives does not cause a meaningful recall loss, then confirm it on Stage 2 seam metrics.
  7. Check the caliper interpretation and coordinate alignment. Confirm whether the caliper values are diameters or radii, whether image coordinates use the same origin and scaling as the image file, and whether missing measurements are common. A wrong conversion changes every pseudo-mask radius and can depress all three mask metrics even when centre detection is good.
  8. Compare instance-aware decoders. The present decoder assigns foreground pixels to the nearest predicted centre inside a radius and falls back to a circle when foreground support is weak. This is fast and simple, but its shape family is limited. Once trusted masks are available, compare a HoVer-Net-style centre-distance representation or a contour/embedding head to test whether touching nuclei separate better and AJI/PQ rise for the right reason.

“These steps distinguish model changes from measurement fixes. Better matching can correct reported P/R/F1. More appropriate training examples can change predictions. Manually traced masks and correct case grouping determine whether the resulting scores support a trustworthy claim.”

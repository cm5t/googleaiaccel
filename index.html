02 · Data and targets

What one training example contains

The code converts each annotated cell into several learning targets. This gives the small model more useful signals than a single “cell / not cell” label.

Input and annotations

A 512 × 512 RGB patch is paired with CSV rows that contain pixel coordinates.

  • Centroid X/Y: the labelled centre of each cell.
  • Max/min caliper: used to estimate a radius as 0.5 × √(max × min), under the current assumption that calipers are full axis lengths.
  • Approximate mask: a filled disk around each centre, clipped to the image boundary.

Training-only variety and background balance

Augmentation is applied only to training crops: flips and right-angle rotations change orientation, while modest brightness, contrast, saturation and channel-gain changes vary appearance. A scale change is sampled occasionally between 0.90× and 1.10×, and the cell centres, radii and targets are transformed with the pixels. Each fold retains every positive crop and samples at most half as many empty crops as positive crops. Validation remains unaugmented and keeps all its patches.

Why predict several targets?

The centre map answers “where is a cell?”, foreground answers “which nearby pixels belong to cell-shaped regions?”, offsets correct the coarse two-pixel output grid, and radius supplies a size estimate. The density map is a separate auxiliary count signal: every point’s Gaussian is normalized to one unit, so nearby kernels can overlap without changing the total target count. The detector still creates individual instances from centre peaks; the density map does not add a second set of detections.

i
Annotation assumption: the CSV provides centre coordinates and caliper measurements, not traced outlines. The current radius formula assumes both calipers are full axis lengths, then halves the geometric mean. Generated circular masks are therefore pseudo-labels for training and mask metrics, not verified cell boundaries. Border clipping keeps a cell target usable when its estimated circle extends beyond the image.

04 · The network

CentroidLite predicts six maps at once

The compact network replaces a large object-detection stack with six aligned maps. Think of it as asking six small questions at every location: “Is a centre here?”, “Is this cell area?”, “How far is the centre?”, “How large is it?”, and “How many cells are nearby?” Its smaller architecture aims to reduce compute; actual speed still depends on hardware, data loading and cell density.

i
Small output map: a 512-pixel patch becomes 256 × 256. The parallel dilation-1/2/4 branches mix local nuclear texture and wider tissue context. Learned offsets recover sub-grid centre precision, and the initial density bias is chosen to avoid an almost-closed softplus gradient.
The training objective
L total = L centre + L foreground + 2L offset + L radius + 0.08L density + 0.10L log-count

Centre uses focal-style supervision and mines difficult negatives. Foreground combines weighted binary cross-entropy with Dice loss. Density uses pixelwise Smooth L1 against normalized point kernels; log-count compares the sum of predicted density with the exact labelled cell count. The density map also supplies a modest candidate-score agreement cue. Loss scales depend on the architecture and reduction rules, so raw total loss should not be compared directly with unrelated models.

05 · Core training loop

What happens during one batch

Choose a step to see what the notebook is doing. The same order repeats for each batch in the epoch.

Load a batch

The dataset returns a list of image tensors and matching dictionaries of cell targets. Images are augmented in training; validation data is left unchanged.

↻
Recoverable training: the loop writes progress checkpoints during an epoch, including model and optimizer state, batch order and the next sample position. If a batch exceeds MPS memory, the code can halve the batch size and retry from saved progress.

What gets logged and saved?

The run prints a progress bar and a persistent summary every 100 batches with recent loss components, throughput and time spent waiting for data. A resumable state is refreshed every ten completed batches, including model, optimizer, scheduler, scaler, fixed epoch order and next sample offset. A separate model-weight file is saved after each completed epoch. If MPS memory runs out, the loop can lower batch size and retry from the last saved position; an interrupted accelerator operation is not guaranteed to be recoverable.

Why macOS starts with zero data workers

The notebook uses zero DataLoader workers by default on macOS because spawned Jupyter workers previously failed to import the dataset class and could increase memory pressure. The separate cell_dataset_workers.py makes dataset definitions importable if workers are deliberately enabled. More workers are not automatically faster on a memory-limited Mac; compare batches per second and data-wait time on the actual machine.

Why group by image instead of randomly splitting patches?

Nearby patches from the same slide can look very similar because they share stain, scanner, tissue and preparation characteristics. If patches from one image appeared in both training and validation, validation could reward recognition of slide-specific patterns. Holding out the whole image asks the harder and more useful question: can the model work on a different image group?

What goes into the training and validation side?

Each training fold keeps every cell-containing patch and adds a reproducible sample of empty patches: up to 0.50 empty patch per positive patch. This gives the detector examples of annotated background without letting a very large number of empty crops dominate each epoch. Validation uses the complete held-out patch set, including empty patches. Where edge-anchored crops overlap, ownership-core bounds assign each labelled centre to one validation crop so it is not counted twice.

Does each fold contain exactly one-third of the images?

Not necessarily. The splitter assigns whole image groups and balances patch and annotated-cell totals; it cannot split an image. A very large or cell-dense image can make exact fractions impossible. The setup prints each fold’s groups, patches and annotated-cell totals for inspection.

What does the epoch cap mean?

Stage 1 allows up to 10 epochs in each of 3 folds (up to 30 CV fold-epochs), plus a final all-data refit capped at 10 epochs. The final refit uses the median selected best epoch from the three folds. Early stopping or a lower median can reduce the total; the 40-epoch figure is a ceiling, not a promise.

How does a fold choose its checkpoint?

The primary fold metrics use a pre-set 0.10 score cutoff; threshold-calibrated metrics are reported separately. Predicted centres are matched one-to-one to labels within 12 pixels. The matcher searches for the largest valid match set, so an early nearest-pair choice cannot unnecessarily block another possible match in a crowded area. Checkpoint selection combines fixed-cutoff F1 (45%), the weaker of precision/recall (25%), and normalized count skill (30%). The scheduler watches fixed-cutoff F1. From epoch 3, later weights are averaged (SWA); the averaged model is used only when its declared validation selection score improves.

What is the difference between cross-validation and the final refit?

The three fold runs estimate how the model behaves on held-out image groups and select the median best epoch. The final refit starts a fresh model and trains on all eligible training patches for that many epochs, capped at 10. It has no held-out group of its own, so cross-validation—not the final fit—is the generalization estimate.

How are Stage 1 and Stage 2 evaluated across folds?

Stage 1 scores held-out patches using centre matching. Stage 2 loads the corresponding fold’s best checkpoint and evaluates complete held-out images with overlapping tiles and de-duplication. This lets the code measure seam errors and whole-image counts without using that fold’s held-out labels to update model weights.

Why can validation take time?

Every fold validates its held-out patches at each epoch. Detection validation sweeps several score thresholds. At the end of a fold, Dice, AJI and PQ require instance-mask comparisons on its best checkpoint, which is a separate and more expensive pass.

How to read a fold result responsibly

A fold line is a small report card for one held-out set. Read the detection measures together and compare the same metrics across all three folds.

  • Training loss falls, validation F1 rises: encouraging, provided the other folds show a similar pattern.
  • Loss falls but validation F1 stalls or falls: the model is fitting the training examples without improving held-out detections; more epochs alone may not help.
  • Low precision or positive count bias: there are likely too many predicted centres. Raise confidence threshold only if validation shows that precision improves without unacceptable recall loss.
  • Low recall or negative count bias: cells may be missed. A lower cutoff may recover detections but can also admit false positives.
  • One fold is much worse than the others: inspect its held-out images for staining, scanning, tissue density or annotation differences before changing the network.
  • Any NaN loss: treat it as a numerical warning. Validation can still produce finite scores from the saved weights, but the affected epoch’s reported mean loss is not trustworthy and the batch that first became non-finite should be investigated.
↗
For a fair summary: report each fold and the mean plus spread across folds, then report full-slide Stage 2 metrics separately. Do not quote the best fold alone as the expected performance.

!
Why not pick the lowest loss? Training loss is a weighted sum of different tasks. The fold checkpoint uses a declared composite of fixed-cutoff F1, the weaker of precision/recall and normalized count skill. Lower loss can coexist with worse cell detections.
07 · Whole-slide use

Stage 2 tiles, overlaps and stitches

Stage 2 is an inference and assembly procedure around the same trained model. It handles cells near crop boundaries and merges repeated views.

A

Overlap tiles

512-pixel crops use a nominal 384-pixel maximum step, giving at least 25% overlap. Starts are spread evenly and the last crop is anchored to the far image edge.

B

Shift to slide space

Each crop's centre, box and mask coordinates are shifted by its slide origin.

C

Fuse repeat views

Only candidates from different tiles can merge. Radius-aware centre distance plus mask IoU or containment must support a duplicate; same-tile neighbours stay distinct.

D

Write outputs

Optional global label map, detection CSV, JSON metadata and coloured overlay.

Why overlap matters

A cell cut by an internal crop edge may look incomplete. Another tile can show it with more context. The code scores each view using detector confidence and distance from an internal cut, scaled by the estimated cell radius; a small nucleus does not need the same margin as a large one. Real outer slide borders are not treated as artificial crop seams. Repeated centres, boxes, radii and scores are combined with quality-and-confidence weights, while the strongest view supplies the instance mask.

How it avoids unsafe merging

The stitcher compares packed instance masks in slide coordinates. Close candidates need sufficient overlap or containment; candidates beyond the standard centre-distance range need stronger mask agreement. A cluster may contain at most one candidate from any one tile, which prevents a third partial view from joining two neighbouring cells that were visible together in the same tile. These are explicit duplicate rules, not a guarantee that every merge is correct.

How the code checks stitching

Each fold’s held-out source images are processed at a fixed 0.10 detection cutoff using that fold’s best Stage 1 checkpoint. Stage 2 reports full-image precision, recall, F1, count MAE and exact-count accuracy, then separately reports a 32-pixel seam band, the full overlap region, and tile interiors. It also reports the fraction of final detections supported by multiple tile views and the mean contributing views. A held-out example can be exported as an instance-label map, per-cell CSV, JSON metadata and coloured overlay.

↗
Read seam results as a diagnostic: similar seam and interior F1 suggests that crop boundaries are not the only source of error. Lower seam scores point toward truncation or duplicate handling. Higher seam scores do not prove the stitcher is better; compare the same held-out images, threshold and fold assignments.
09 · Code map

Functions worth knowing

Open a name to see the job it performs. The helper module stays beside the notebook so dataset definitions can be imported by macOS worker processes if workers are enabled.

CellDataset.__getitem__()

Loads one crop, maps global CSV coordinates to local coordinates, builds approximate masks and target maps, then applies training-only flips, rotations and mild stain/intensity changes.

edge_anchored_patch_starts() + tile_ownership_intervals()

Ensure the final crop reaches the image edge and assign every cell centre to one validation core, even where crops overlap.

grouped_kfold_splits()

Creates three Stage 1 folds without importing scikit-learn. It keeps image groups intact and greedily balances both patch volume and annotated-cell counts.

CentroidLiteNet._losses()

Compares six outputs with centre, foreground, offset, radius and count-conserving density targets. It returns separate centre, foreground, offset, radius, pixel-density and log-count loss parts.

CentroidLiteNet._decode_one()

Blends centre confidence with modest foreground and density support, finds local peaks, removes almost-coincident peaks within the configured four-pixel minimum distance, applies centre offsets, converts predicted radii to pixels, groups foreground pixels around centres, and derives approximate masks and boxes. The centre head still proposes the detections.

train_one_epoch() + run_resumable_epoch()

Performs the batch learning steps, prints periodic statistics, saves recoverable progress and handles a retry with a smaller batch after an MPS out-of-memory error.

validate()

Matches predicted centres to labelled centres, sweeps score thresholds, aggregates precision/recall/F1 and count errors, and scores instance masks on the selected best checkpoint.

stage2_predict_full_image() + _deduplicate_stage2_candidates()

Runs overlapping crop inference in batches, moves detections into full-slide coordinates, rates each view by confidence and cell-size-aware distance from internal crop cuts, then checks cross-tile centre distance and packed-mask IoU/containment before merging. It fuses centre, box, radius and score estimates, keeps a representative mask, and optionally writes a disk-backed global label map, per-cell CSV, JSON metadata and overlay.

10 · Read this carefully

What this model does not prove

Research prototype, not a clinical tool.

The masks are approximate circles derived from centroid and caliper labels; they are not manually traced cell boundaries. Training retains every cell-containing patch and samples empty patches at 0.50 per positive patch; validation keeps the full held-out patch set, including empty patches. The threshold sweep and all reported metrics still need to be checked on held-out data. Dice, AJI and PQ are measured against caliper-derived circular pseudo-masks, not manually traced boundaries. This guide uses invented examples only; it does not load confidential images, CSVs, model weights or checkpoints and does not promise a target score.

01 · The big picture

From slide pixels to cell-level results

The pipeline uses one compact network. “Stage 1” and “Stage 2” describe two ways of using its predictions, not two separately trained networks.

Predict cells patch by patch: centres, scores, masks and boxes.

Why two stages? A network sees a manageable crop. Stage 2 handles the bookkeeping needed to turn many crop predictions into one slide-wide map and count.
02 · Data and targets

What one training example contains

The code converts each annotated cell into several learning targets. This gives the small model more useful signals than a single “cell / not cell” label.

Input and annotations

A 512 × 512 RGB patch is paired with CSV rows that contain pixel coordinates.

  • Centroid X/Y: the labelled centre of each cell.
  • Max/min caliper: used to estimate a radius as 0.5 × √(max × min), under the current assumption that calipers are full axis lengths.
  • Approximate mask: a filled disk around each centre, clipped to the image boundary.

Border-aware patching

edge_anchored_patch_starts() shifts the final crop to the far image edge instead of leaving a strip uncovered.

04 · The network

CentroidLite predicts five maps at once

The compact network trades a large object-detection stack for a small set of dense maps. Its smaller architecture aims to reduce compute; actual speed still depends on hardware, data loading and cell density.

1 · Centre confidenceHow likely is a cell centre at this output location?
2 · ForegroundHow likely is this location part of a cell?
3–4 · X/Y offsetsFine-tune the centre within the 2-pixel output grid.
5 · RadiusPredict a normalized size, then scale it to pixels.
i
Small output map: the 512-pixel patch is downsampled to 256 × 256, so each prediction point represents roughly a 2 × 2 pixel area. The learned offsets help recover more precise centres.
The training objective
L total = L centre + L foreground + 2 × L offset + L radius + 0.10 × L count

Centre uses a focal-style positive/negative penalty with hard-negative mining. Foreground combines weighted binary cross-entropy and Dice loss. The count term compares heatmap mass with target-centre density. These terms have different scales, so raw total loss is not directly comparable with an older code version.

The held-out fold rotates five times. Each fold is capped at 5 epochs in the current setup. After cross-validation, the code refits on all eligible training patches for up to 5 epochs, using the median best-fold epoch count.

!
Why not pick the lowest loss? Training loss is a weighted sum of different tasks. The fold checkpoint is selected mainly by validation F1, with count MAE as a tie-break. Lower loss can coexist with worse cell detections.
07 · Whole-slide use

Stage 2 tiles, overlaps and stitches

Stage 2 is an inference and assembly procedure around the same trained model. It handles cells near crop boundaries and merges repeated views.

A

Overlap tiles

512-pixel crops move by 75% of patch width, giving a 25% overlap.

B

Shift to slide space

Each crop's centre, box and mask coordinates are shifted by its slide origin.

C

Remove duplicates

Near-identical centres from different tiles compete; edge-aware quality favours a less-truncated view.

D

Write outputs

Optional global label map, detection CSV, JSON metadata and coloured overlay.

Why overlap matters

A cell cut by a crop edge may look incomplete. Another overlapping tile can show the same cell with more context. Stage 2 ranks candidates using confidence and distance from that tile's edge, then suppresses duplicates only across different tiles.

How the code checks stitching

On held-out full slides, Stage 2 reports precision, recall, F1 and count MAE. It also separates detections near tile seams from detections in tile interiors to show whether boundaries remain a problem.

08 · Code map

Functions worth knowing

Open a name to see the job it performs. The helper module stays beside the notebook because macOS worker processes need importable dataset definitions.

CellDataset.__getitem__()

Loads one crop, maps global CSV coordinates to local coordinates, builds approximate masks and target maps, then applies training-only flips, rotations and mild stain/intensity changes.

edge_anchored_patch_starts() + tile_ownership_intervals()

Ensure the final crop reaches the image edge and assign every cell centre to one validation core, even where crops overlap.

grouped_kfold_splits()

Creates five balanced folds by image group without importing scikit-learn. Keeping all patches from a slide together reduces data leakage.

CentroidLiteNet._losses()

Compares predicted centre, foreground, offsets, radius and count consistency with the target maps; returns separate loss parts for the batch logger.

CentroidLiteNet._decode_one()

Finds local heatmap peaks, applies the centre offsets, converts predicted radii to pixels, groups foreground pixels around centres, and derives masks and boxes.

train_one_epoch() + run_resumable_epoch()

Performs the batch learning steps, prints periodic statistics, saves recoverable progress and handles a retry with a smaller batch after an MPS out-of-memory error.

validate()

Matches predicted centres to labelled centres, sweeps score thresholds, aggregates precision/recall/F1 and count errors, and scores instance masks on the selected best checkpoint.

stage2_predict_full_image()

Runs overlapping crop inference, moves detections into full-slide coordinates, deduplicates cross-tile candidates, and optionally writes masks, tables and overlays.

09 · Read this carefully

What this model does not prove

Research prototype, not a clinical tool.

The masks are approximate circles derived from centroid and caliper labels; they are not manually traced cell boundaries. The current training split filters empty patches, so it may have fewer fully blank examples to teach false-positive rejection. The threshold sweep and all reported metrics still need to be checked on your real, confidential data. This guide uses a schematic only and does not run inference or promise a target score.
